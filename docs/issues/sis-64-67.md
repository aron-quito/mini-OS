## 1. Resumen de las 4 Issues Implementadas

### 🛡️ Issue 8.1 (`SIS-64`): Manejadores de señales del sistema con `sigaction`
- **`SIGCHLD` (`sigchld_handler` en [`src/process/signals.c`](file:///Users/luisc/Documents/mini-OS/src/process/signals.c)):**
  - Configurado mediante `sigaction` con `SA_RESTART | SA_NOCLDSTOP`.
  - Cuando no hay un proceso en foreground bloqueando (`s_fg_pid == 0`), cosecha inmediatamente en un bucle `waitpid(-1, &status, WNOHANG)` cualquier hijo finalizado en background y almacena `(pid, status)` en un búfer circular *async-signal-safe* (`s_reap_ring`).
  - Erradica procesos `<defunct>` (zombies) en tiempo real sin invocar funciones no reentrantes (`printf`/`malloc`/`free`) dentro del manejador de señal.
  - Antes de cada prompt, [`process_reap_bg()`](file:///Users/luisc/Documents/mini-OS/src/process/process.c#L417-L430) drena `signals_pop_reaped()`, actualiza `s_bg_table`, libera la RAM simulada con `memory_free(pid)` y promueve procesos en `mem_queue`.
- **`SIGINT` (`sigint_handler` en [`src/process/signals.c`](file:///Users/luisc/Documents/mini-OS/src/process/signals.c)):**
  - Captura `Ctrl+C` con `sigaction`. Si el usuario está en el prompt (`s_fg_pid == 0`), escribe `"\nminiOS> "` mediante `write(STDOUT_FILENO, ...)` sin cerrar el shell.
  - Los procesos en background se aíslan con `setpgid(0, 0)` y `signal(SIGINT, SIG_IGN)` en [`process_spawn_bg()`](file:///Users/luisc/Documents/mini-OS/src/process/process.c#L304-L312) para que `Ctrl+C` no los termine accidentalmente.

### 🔍 Issue 8.2 (`SIS-65`): Validación estricta de entradas y mensajes de error
Se estandarizaron las validaciones defensivas en todos los comandos del shell para prevenir *Segmentation Faults* ante entradas malformadas:

| Entrada errónea | Respuesta del sistema verificada |
|:---|:---|
| `mem-alloc` (sin args) | `Uso: mem-alloc <pid> <size_kb>` |
| `mem-alloc -5 200` | `[ERROR] El PID debe ser un entero positivo (recibido: '-5').` |
| `mem-alloc 42 0` | `[ERROR] El tamaño debe ser un entero positivo (> 0 KB) (recibido: '0').` |
| `mem-alloc 10 128` (PID ya activo) | `[ADVERTENCIA] El PID 10 ya tiene 256 KB asignados en memoria. Use 'mem-free 10' antes de reasignar.` |
| `mem-config page 50` | `[ERROR] El tamaño de página (50 KB) debe ser potencia de 2. Valores validos: 4, 8, 16, 32, 64, 128, 256...` |
| `switch-ram invalid` | `Uso: switch-ram [ff\|pag]` |
| `thread-demo 0 2 10` | `[ERROR] Se requieren mínimo 2 productores y 2 consumidores (recibido: productores=0, consumidores=2).` |

### 🧪 Issue 8.3 (`SIS-66`): Batería de pruebas integradas (`UC-00` a `UC-06`)
Se ejecutó de extremo a extremo la suite de casos de uso documentados en `docs/use-cases/`:
- **UC-00 (Shell Base):** REPL, `help`, `clear`, `exit`, manejo de EOF (`Ctrl+D`) e interrupción `Ctrl+C`.
- **UC-01 (Procesos):** Ejecución en foreground (`echo`), ejecución asíncrona en background con reserva de RAM (`sleep 1 64 &`), tabla `ps-mini` y cosecha automática al finalizar.
- **UC-02 (First-Fit):** Configuración con `mem-config`, partición dinámica (`ff_alloc`), fragmentación externa y coalescencia automática (`ff_free`).
- **UC-03 (Paginación):** Asignación de marcos con división techo (`pag_alloc`), visualización `mem-page-table <pid>`, traducción `mem-translate <pid> <dir>` y detección de fallos de segmentación.
- **UC-04 (`switch-ram`):** Conmutación inmediata sin carga, confirmación interactiva `[s/N]` bajo carga y transición atómica `FF -> PAG -> FF` verificada con `mem-view`.
- **UC-05 (Hilos):** Ejecución concurrente `thread-demo` y certificación de `0` pérdida de datos con `thread-stats`.
- **UC-06 (`mem_queue`):** Encolado reactivo por falta de memoria y promoción automática FIFO (`[AUTO-ALLOC]`) tras `mem-free`.
